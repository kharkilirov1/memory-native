# LUT-GEMM on the packed group-ternary format — measured 2026-10-17 (A100)

Does the Method-of-Four-Russians matmul actually beat the existing decode paths? Measured,
single-token decode, one layer.

Setup: NVIDIA A100-SXM4-40GB, torch 2.11.0+cu130, Triton 3.6.0, layer 4096x4096,
`group=128`, `C=11`, `residual_alpha=0` (strict readout), M=1, medians from
`torch.utils.benchmark.blocked_autorange`. Driver: `scripts/bench_lut_gemm.py`.

| path | ms | packed-state GB/s |
|---|---:|---:|
| decode-once to fp32 + cuBLAS | 1.877 | 6.7 |
| in-repo fused decode-in-GEMM (Triton) | 1.411 | 8.9 |
| **LUT: 81 partial sums + gather-add** | **0.517** | **24.4** |
| bandwidth floor at ~1.8 TB/s | 0.007 | 1800 |

Correctness: the Triton kernel matches the exact decoded weight with **max relative error
1.8e-07** (fp32); the torch reference is CPU-tested for exactness against
`x @ visible_weight().T`, including the act-order permutation and group scales
(`tests/test_lut_gemm.py`, 5 tests).

## What this says

- LUT is **2.7x faster than the existing fused decode-in-GEMM** and 3.6x faster than
  decode-once + cuBLAS for single-token decode on this layer.
- All three paths are **70-270x off the bandwidth floor** at M=1 (12 MiB of packed state
  in 0.5-1.9 ms), so the layer is nowhere near memory-roofline here; the fused decode
  path is ALU/occupancy-bound, which is exactly the regime LUT attacks. The result is
  therefore a genuine gap-closing, not a roofline miracle.
- Scope limits, stated up front: the kernel handles **M=1 only** (the table is per token:
  M x K/4 x 81 floats, and gather traffic would dominate at batch sizes), the LUT path
  currently **ignores the salient channel** (it needs the same sparse correction the other
  paths apply: `y += A_salient @ x`), and it applies only to the **strict alpha=0** readout
  because at alpha>0 the weight is not ternary. Prefill (M>1) is untested and expected to
  lose to tensor cores.

## Status

Experiment, not a production path: there is no `kernel_mode="lut"` hook. To use it, add
salient handling, then a decode hook, then re-measure end-to-end (the decode step is one
part of a token's cost, and the LUT build itself is a torch einsum that must be folded in).
The numbers above are the reason to do that work, not proof that it pays end-to-end.
